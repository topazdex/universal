# Routing API hardening — September 12, 2026

**Status: deployed September 12, 2026 (UTC 23:17, Fly version 17; version 18 at 23:25 added Base and Ethereum fallback endpoints).** `topaz-routing-api` runs two warm `shared-cpu-2x`/1 GiB Machines in `ord` on image `deployment-01M2BYYM4BM1GX27CYR2T3CE3K`; no production secrets are set, so every chain is on public RPCs. Before the rollout the multicall transport guard was found to be ineffective through ethers' `CALL_EXCEPTION` wrapper and was fixed, along with a 502 for unresolvable tokens and the fork suite's timeouts; see commit `fb856e1`.

The public quote endpoint now rejects malformed or expensive routing parameters before provider work. Supported request limits are maxHops 1–3, maxSplits 1–4, distributionPercent 5/10/20/25/50/100, integer slippageBips 0–5000 and deadlineSeconds 30–3600. Amounts are positive uint256 raw units; addresses and signed Permit2 field widths are validated. Existing GET/POST, exact-input/output and calldata responses remain supported.

Per Machine: eight active quote requests; visitor token bucket of 20 requests with five replenished per second; bounded 10,000 visitor entries; IPv6 grouped by /64. Fly-Client-IP is trusted only on Fly. Forwarded headers do not replace visitor identity. Quotas are per process, so two replicas allow up to twice one replica's quota. HTTP JSON bodies are limited to 16 KiB, URLs 8 KiB, receive time 10 seconds, headers 64. Saturation returns 503, rate limiting 429; both include Retry-After. Errors hide provider URLs/credentials. Health remains responsive without running a quote.

Each computed quote has a 12-second deadline and at most 160 RPC attempts. Actual fetch requests and response bodies are cancelled on expiry; individual RPC attempts, including queue wait, are limited to three seconds and responses to four MiB. A process-wide gate permits 12 RPCs in flight and 48 queued across all chains and Multicall invocations. Only routing read/simulation RPC methods are supported. No event-log scan is used. Subgraph discovery has its own five-second/four-MiB bounds and shared in-flight refresh; a discovery already in flight can finish after an abandoned client, but no new RPC work proceeds past the quote budget. An abandoned client does not cancel a quote still shared by other callers; admission remains occupied until that bounded computation ends.

Transport outages are propagated instead of recursively splitting failed Multicalls. Deterministic gas/revert failures still isolate failing calls. Route generation has a 100,000-edge work bound, and SDK routing settings have the same finite safety bounds. The one-second quote cache coalesces identical work. Signed permits bypass it. Explicit refresh recomputes live state/calldata without refetching discovery; SDK refreshPools remains available for intentional pool discovery refresh. Quotes stay pinned to one block. Token metadata is capped at 2,000 entries per chain.

Secrets ROUTING_RPC_URLS_56, ROUTING_RPC_URLS_4663, ROUTING_RPC_URLS_8453 and ROUTING_RPC_URLS_1 override public endpoints even when CHAINS_CONFIG_FILE is used. Each accepts a comma-separated list, with up to two endpoints used and network identity verified. Use Fly secrets; never commit authenticated URLs. Private endpoints were validated with normal quote requests on all four chains.

The prepared Fly configuration requests two warm shared-cpu-2x/1-GiB Machines in ord, with request concurrency soft 6 / hard 12. The quote and RPC admission limits enforce the application budget independently. SIGTERM drains requests for up to 15 seconds. /health is liveness, not proof that every provider can quote; monitor real quote success on all four chains. No automatic cross-region failover or unbounded machine scaling is claimed.

The earlier patch passed 121 hermetic tests and eight real unsigned quote checks. Source hashes and local validation receipts are in ../topaz-api/docs/evidence/launch-completion-20260912/routing/. At deployment the full suites passed — routing-api 85/85, smart-order-router 59 (6 spoke tests skipped without their RPCs), sdk-core 15/15 — and live smoke checks covered exact-input and exact-output quotes on all four chains, calldata generation, the 400 paths for unresolvable tokens, invalid split steps, mismatched native aliases and unknown chains, the `Cache-Control: private, no-store` header, and 12 consecutive cache-bypassed Base quotes after the fallback endpoint went in. Tests cover invalid inputs before RPC, actual socket cancellation, global queue recovery, cache replacement races, private RPC overrides, multichain requests and outage amplification. Read-only exact-input/output transaction construction is sampled on all four chains. No local Docker containers or live transaction submissions are used.
